# 개인 자료 아카이빙 프로그램 최종 기획과 개발 기준

작성일: 2026-10-05. 프로젝트 가칭: RefArchive.

## 목표

그림 참고 자료를 중심으로 이미지·링크·문서를 수집하고, 사용자의 키워드로 정리·검색·재활용하는 개인 자료함을 제작한다. 이후 학습 자료·기술 문서에도 같은 구조를 활용한다.

사용자와 확정한 자동 분류 규칙: **키워드별 직접 분류 자료 10개는 자동 분류 활성화 최소 조건이며 저장 상한이 아니다.** 조건을 충족해도 사용자가 직접 켜야 한다. 키워드별로 켜고 끌 수 있으며 꺼도 기존 자료와 키워드를 유지한다.

초기 구현은 Windows에서 실행하는 로컬 앱으로 한다. 원본과 SQLite를 PC에 보관하고 기본 저장·검색은 오프라인으로 제공한다. 첫 버전은 브라우저 화면과 루프백 서버로 구성하며, Windows 설치형 패키징은 별도 작업이다.

## 다른 분야에서 참고한 구조

- Eagle: 일괄 키워드 정리, 스마트 폴더, 동일 파일 확인. https://en.eagle.cool/support/desktop/organize
- Zotero: 하나의 자료를 여러 모음에 연결하고 원본을 복제하지 않음. https://www.zotero.org/support/collections_and_tags
- Paperless-ngx: 원본 보존, OCR 내용 검색, 사용자 승인·거절 기반 분류 제안. https://docs.paperless-ngx.com/usage/
- Raindrop.io: 본문·메모 검색과 웹페이지 보관, 깨진 링크 표시. https://help.raindrop.io/using-search 및 https://help.raindrop.io/broken-links
- Immich: 의미 검색과 사용자 검토를 거치는 시각적 중복 확인. https://docs.immich.app/features/searching/ 및 https://docs.immich.app/features/duplicates-utility/
- calibre: 검색 조건으로 갱신하는 가상 자료함. https://manual.calibre-ebook.com/virtual_libraries.html
- PureRef: 이미지 비교, 참고 보드, 항상 위 보기. https://www.pureref.com/handbook/features/

위 공식 기능을 참고한 설계이며 경쟁 제품의 성능·정확도를 이 프로그램에 그대로 적용하지 않는다.

## 정리와 수집

- 카테고리: 큰 분야. 예: 인체, 의상, 배경, 강의, 개발.
- 키워드: 특징과 검색 기준. 예: 손, 갑옷, 역광, 숲.
- 자료 모음: 프로젝트별 선택 묶음. 예: 캐릭터 A, 배경 연습.
- 자료 하나는 여러 카테고리·키워드·자료 모음에 연결되지만 원본은 한 번 저장한다.
- 파일 선택·드래그·클립보드·링크로 자료를 추가한다.
- 여러 자료에 분류를 일괄 적용한다. 키워드를 생략하면 미분류함에서 나중에 정리한다.
- 원본·제목·자료 유형·메모·출처·작가 정보·등록 날짜·즐겨찾기를 보관한다. 확인된 이용 조건만 기록한다.
- 같은 파일과 시각적으로 비슷한 파일을 구분한다. 유사하다는 이유로 자동 삭제하지 않는다.

## 검색과 활용

- 키워드·제목·파일명·메모·출처 검색, 키워드 모두 포함/하나 이상 포함/제외.
- 카테고리·유형·등록 날짜·즐겨찾기·형태·해상도 필터.
- 자주 쓰는 검색 조건은 스마트 자료함으로 저장하고 조건에 맞는 새 자료를 자동으로 보여 준다. 이것은 AI 키워드 분류와 다른 기능이다.
- 키워드 추가·변경·병합과 자료의 분류 일괄 편집. 병합 후 분석 사례 수를 중복 없이 다시 계산한다.
- 후속 단계에서 PDF 텍스트·OCR·자연어 검색·유사 이미지·색감 검색을 추가한다.
- 검색 자료를 작업 모음과 비교 보기로 연결한다. 자유 배치 보드·관심 영역 메모·항상 위 보기는 후속 단계다. 원본은 덮어쓰지 않는다.

## 자동 분류

- 서로 다른 확정 이미지 10개 이상인 키워드부터 켤 수 있다. 동일 파일·휴지통·확인 전 자동 결과는 사례에서 제외한다.
- 모드: 끄기 / 추천만 받기 / 자동 적용. 처음 활성화할 때 추천 모드를 기본으로 제안하되 사용자가 선택한다.
- 자료가 10개 미만으로 줄면 새 자동 분류를 일시 중단하고 기존 결과는 보존한다.
- 사전 학습 모델의 이미지 특징과 사용자 사례를 비교하는 방식부터 검증한다. 키워드 설명도 참고한다.
- 해당 키워드가 없으면 미분류, 여러 키워드가 맞으면 다중 적용한다. 수동 키워드를 덮어쓰지 않는다.
- 추천 이유로 유사 사례를 제시한다. 유사도 점수를 정확도 백분율로 표기하지 않는다.
- 승인·거절·수정 기록을 참고하고 자동 결과를 검토 없이 재사용하지 않는다.
- 새 키워드 생성과 카테고리 자동 배치는 초기 AI 범위에서 제외한다.
- 전체 재분류는 별도 실행과 적용 전 확인을 제공한다.
- 원본 저장 후 백그라운드 분석한다. AI 실패가 저장과 수동 분류를 막지 않는다.
- 10개는 정확도 보장이 아니다. 한국어·그림체·자세·구도를 실제 자료로 검증한 뒤 모델과 기준을 선정한다. CLIP 한계 참고: https://github.com/openai/CLIP/blob/main/model-card.md

## 링크·문서 확장

- 링크와 파일 저장 상태를 구분한다. 지원되는 링크는 대상 이미지를 선택해 저장한다. 모든 사이트의 다운로드를 약속하지 않는다.
- 공식 제공 방식과 사이트 조건을 확인하며 접근·저장 제한을 우회하지 않는다. 링크 접근 실패만으로 삭제하지 않는다.
- Pinterest: https://help.pinterest.com/en/article/download-an-image
- YouTube: https://www.youtube.com/static?gl=KR&template=terms
- PDF와 OCR 결과는 원본과 분리한다. 검색 결과에서 문장·페이지로 이동하고 OCR 수정도 지원한다.
- 설명과 텍스트를 요약해 원문 근거와 연결한다. 사용자 메모와 AI 요약은 구분한다. 정보가 부족하면 요약 불가로 표시한다.
- 요약에서 추출한 키워드는 확인 후 검색에 연결한다. 10개 활성화와 요약 기능은 별도다.
- 외부 AI 전송 범위·비용을 설명하고 명시적으로 켜게 한다. 자동 분류·OCR·요약 설정은 분리한다.

## 보관과 화면

- 원본 복사 저장, 별도 미리보기, 분류 제거와 자료 삭제 구분.
- 휴지통 복원, 원본과 메타데이터 동시 백업, 다른 위치에서 복원 검증, 원본·메타데이터 내보내기.
- 화면: 전체 자료함 / 미분류함 / 상세 / 분류 관리 / 분류 확인함 / 스마트 자료함·자료 모음 / 설정·백업.

## 개발 순서

2026-10-05 구현 현황: 저장 검색, 자료 모음·이미지 비교, 로컬 CLIP 분류·확인함·유사 이미지 검색, PDF·Windows OCR·원문 문장 추출 요약·키워드 후보, 공개 링크의 정지 이미지 저장과 백그라운드 실행·바로가기를 추가했다. 초기 요약은 생성형 AI가 아닌 원문 문장 추출 방식이다. 모델 정확도는 실제 사용자 자료로 별도 평가해야 하며 영상·보드·자연어 검색·클라우드·설치형 배포는 후속 범위로 남긴다.

1. 기본 아카이브: 이미지·링크 저장, 카테고리·키워드, 검색·일괄 편집, 출처·메모·즐겨찾기, 동일 파일 확인, 휴지통, 백업·복원·내보내기.
2. 정리 효율: 저장 검색, 키워드 병합, 자료 모음, 비교 보기, 분류 확인함. 병합은 필요 범위가 작아 1단계에 포함할 수 있다.
3. 자동 분류: 10개 조건, 추천·자동 적용, 설정, 수정 기록, 실제 자료 검증.
4. 내용 분석: 문서·OCR·요약·키워드 후보·지원 링크 다운로드.
5. 활용 확장: 자연어 검색·유사 이미지·보드·영상.

브라우저 확장·모바일·클라우드 동기화·협업·공개 공유는 실제 수요 후 검토한다.

## 검증

대량 업로드·동일 파일·손상 파일·공간 부족, 한국어와 복합 검색, 9/10개 경계·개별 설정·다중 분류·수동 입력 보존, 삭제·분류 취소, 다른 경로 백업 복원, AI·다운로드 실패를 확인한다. AI 평가는 참고 사례와 별도 평가 자료로 수행하고 유사 이미지가 양쪽에 섞이지 않게 한다. 맞게 적용한 비율·놓친 비율·확인 대기 비율·사용자 수정 시간을 키워드별로 기록한다.
