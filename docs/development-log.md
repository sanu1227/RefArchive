# RefArchive 개발노트

각 개발 작업에 날짜, 목표, 변경 내용, 설계 결정, 검증 결과, 남은 작업을 기록한다. 비밀 정보와 실제 사용자 자료 내용은 기록하지 않는다.

## 2026-10-05 — 기본 자료함 첫 구현

### 목표

사용자가 확정한 기획에 따라 실제로 실행 가능한 로컬 자료함을 만들고, 개발 과정과 검증 결과를 함께 보관한다. 첫 작업은 1단계 기본 아카이브 전체를 대상으로 한다.

### 변경 내용

- `archive.py`: SQLite 저장, 이미지 검증·원본 복사·미리보기, 링크 등록, 상세 편집, 다중 카테고리·키워드, 일괄 추가·제거, 동일 파일 확인, 즐겨찾기, 휴지통 복원.
- `web/`: 한국어 자료함, 파일 선택·드래그·클립보드, 복합 검색·분류 필터, 키워드·카테고리 관리, 백업 화면, 좁은 화면 대응.
- 전체 ZIP 백업과 메타데이터 JSON 내보내기. 복원 전에 구조·DB·체크섬·이미지 검증, 현재 자료함의 안전 백업과 이전 폴더 보존.
- `start.cmd`, `start.ps1`, `requirements.txt`: Windows 실행과 프로젝트 전용 Python 환경.
- `docs/product-plan.md`: 확정 기획과 후속 기능·공식 조사 출처 보관.
- `AGENTS.md`: 이후 작업에도 개발노트와 데이터 보존 규칙 적용.

### 설계 결정

- SQLite와 Python 표준 HTTP 서버로 시작하고 이미지 검증·EXIF 방향 미리보기에 Pillow만 사용한다. UI 프레임워크와 외부 API는 추가하지 않는다.
- 현재는 루프백 서버를 브라우저로 이용하는 로컬 앱이다. 설치형 배포·독립 창은 구현 전이며 데스크톱 제품 전체가 완성됐다고 표시하지 않는다.
- 원본은 업로드 바이트 그대로 보존한다. 원본 파일명은 DB에 저장하고 실제 파일명은 내부 식별자로 구성한다.
- 같은 파일은 기존 자료를 재사용하고 새 분류만 추가한다. 기존 제목·메모·출처를 자동 덮어쓰지 않는다.
- 키워드 사례는 휴지통을 제외한 서로 다른 수동 분류 이미지로 계산한다. 링크는 이미지 자동 분류 10개에 포함하지 않는다.
- 10개는 저장 상한이 아니다. 이번 버전은 개수·조건만 표시하고 자동 분류 엔진은 연결하지 않는다.
- 외부 접속은 허용하지 않는다. Host·세션 토큰·Origin을 확인하고 자료 입력은 DOM 텍스트로 표시한다. 외부 URL은 주소로만 보관하고 서버에서 가져오지 않는다.
- 휴지통은 영구 삭제 없이 복원 가능한 상태로 보관한다.
- 업로드 메타데이터는 URL 대신 multipart 본문으로 전송한다. 긴 한국어 메모가 HTTP 주소 길이 한도에 걸리지 않도록 한다.
- 확인과 이름 입력은 앱 내부 대화상자로 제공한다. 모달 내부에도 성공·오류 메시지를 표시한다.
- Windows의 주소 재사용으로 같은 포트에 중복 서버가 생기지 않도록 독점 바인딩한다. 이미 실행 중인 RefArchive는 재사용한다.
- 복원은 현재 라이브러리 교체 방식이다. 검증 실패 시 현재 자료함을 유지한다. 압축 파일과 압축 해제 총량 각각 1 GB까지 지원한다.
- 현재는 전체 메타데이터를 로드해 브라우저에서 검색한다. 큰 라이브러리에서 성능 문제가 확인되면 서버 검색·페이지 단위 조회로 바꾼다.

### 검증 결과

- Python 3.14.7 프로젝트 전용 `.venv`와 Pillow 12.3.0을 준비했다. `powershell -NoProfile -ExecutionPolicy Bypass -File .\start.ps1 -NoBrowser` 실행과 이미 실행 중인 앱 재사용을 확인했다.
- `python -m unittest discover -s tests -v`: **11개 통과**. 원본 바이트 보존·다중 분류·동일 파일 재사용, 9/10개 경계와 11개 이상 저장, 링크·휴지통 제외 집계, 분류 병합과 분류 삭제 시 원본 유지, 일괄 변경의 실패 시 롤백을 확인했다.
- 백업을 다른 디렉터리에 복원하고, 복원 전 안전 백업으로 이전 자료함을 다시 복구했다. 재시작 후 자료·메모·키워드·즐겨찾기·휴지통 상태가 유지됐다.
- 경로 이탈 ZIP, 원본 체크섬 불일치, 누락된 미리보기, 변경된 DB 정의·트리거, 손상 DB·manifest를 거부하고 기존 자료함을 유지했다.
- HTTP 통합 검증: 이미지 등록·수정·원본 조회·백업·복원, 토큰·Origin·Host 확인, 임의 파일 접근 거부, 20,000자 한국어 메모 업로드를 확인했다.
- 같은 포트로 두 번째 서버 실행을 차단하는 테스트를 추가했다.
- `node --check web/app.js`와 Python 컴파일 검증 통과.
- 실제 브라우저: 분리된 `test-results/browser-data`에서 합성 이미지 3개와 링크 1개를 등록했다. 다중 카테고리, 상세 편집, 한국어 메모 검색, 공통 키워드·즐겨찾기, 휴지통 이동·복원, 확인 취소를 확인했다.
- 중복 이미지에 새 분류만 추가되고 자료 수가 늘지 않는 것을 확인했다. 손상 이미지가 실패 목록에 남고 실패한 파일만 재시도 대상으로 유지됐다.
- 백업 생성 응답과 앱 내부 안내 메시지, ZIP 선택·확인·복원 흐름을 확인했다. 인앱 브라우저의 다운로드 이벤트는 시간 초과되어 실제 브라우저 다운로드 파일의 디스크 저장은 확인하지 못했다. ZIP 구조와 원본을 포함한 내보내기·복원은 자동 테스트로 확인했다. 다운로드 안내는 저장 성공 대신 다운로드 요청으로 표기했다.
- 브라우저 기본 확인창 자동화가 멈춰 앱 내부 대화상자로 바꾸고 다시 검증했다. 백업 크기 검사 추가 중 경로와 파일 객체의 차이로 테스트가 실패해 수정했고 최종 11개 테스트가 통과했다.
- 기본 `data/library`는 샘플 없는 **0개 자료** 상태다. 테스트 서버는 종료하고, 기본 앱은 `http://127.0.0.1:18765`에 실행했다. 새 기본 화면에서 브라우저 오류 로그가 없었다.
- 기본 화면: `docs/screenshots/first-run.jpg`. 테스트 자료 화면: `test-results/browser-library.jpg`.
- 미리보기 서버 강제 종료 요청은 도구의 자동 검토에서 `blocked by policy`로 거부됐다. 기존 실행을 유지했고, 실행 중인 서버에 없는 종료 버튼은 배포하지 않았다. 최종 소스는 11개 테스트와 실행 중인 기본 자료함에 맞췄다.

## 2026-10-05 — 로컬 주소 접속 불가 확인

- 목표: 자료함 주소가 열리지 않는 원인을 확인하고 실행을 복구한다.
- 확인: `127.0.0.1:18765`의 페이지와 상태 API 모두 연결이 거부됐고, 해당 포트의 수신 서버가 없었다. 이전 서버가 종료된 구체적인 원인은 확인하지 못했다.
- 조치: 프로젝트 전용 Python 환경으로 서버를 다시 실행했다. 코드와 저장 자료는 변경하지 않았다.
- 검증: `/api/health`의 앱 이름 `RefArchive`, 기본 페이지 HTTP 200, `/api/state`의 자료 0개 응답을 확인했다.
- 실행 안내: 현재 버전은 PC에서 실행하는 로컬 앱이다. `start.cmd`를 실행하고 서버 창을 열어 둬야 주소에 접속할 수 있다. 외부 호스팅과 PC 시작 시 자동 실행은 구현하지 않았다.

## 2026-10-05 — 추가 기능 7개 기본 구현

### 목표와 변경

- 사용자가 확정한 7개 기능 전체를 순차 구현한다. 실제 자료함과 별도의 테스트 자료함을 사용하고, 기존 자료를 보존한다.
- 실행 편의: 창을 계속 열어 두지 않아도 되는 백그라운드 실행, 실행 상태 확인, 바탕화면 바로가기, 앱 내부 정상 종료를 추가했다. `-NoBrowser`는 개발용 전경 실행을 유지한다.
- 저장 검색: 검색어·포함/제외 키워드·유형·정렬·카테고리·자료 모음 조건을 저장하고 다시 적용한다. 조건에 사용된 분류를 삭제해도 검색 범위가 조용히 넓어지지 않게 처리했다.
- 자료 모음과 비교: 원본 복사 없이 자료를 여러 모음에 넣고, 이미지 2~6개를 나란히 비교한다. 모음 삭제와 자료 제외는 원본을 삭제하지 않는다.
- 자동 분류: 키워드별 끄기/추천/자동 적용, 임계값, 근거 이미지 3개, 확인함의 승인·거절을 구현했다. 수동 지정한 활성 이미지 10개가 활성화 조건이며 저장 개수 제한은 아니다. 승인 전 자동 태그는 사례 개수에서 제외한다.
- PDF·OCR·요약: PDF 원본과 페이지별 텍스트, Windows OCR, 원문 문장 추출 요약과 근거 페이지, 후보 키워드 선택, 추출 텍스트 수정, 검색 결과의 관련 페이지 이동을 추가했다. 업로드 시 요약과 OCR은 각각 선택 설정으로 제공한다.
- 링크 이미지 저장: 사용자 허용 후 공개 HTML의 이미지 주소나 직접 이미지 URL을 찾아 선택한 이미지를 원본과 출처로 보관한다. 사설 주소·비표준 포트·사설 주소로의 리다이렉트·과도한 크기를 거부하고 접속 시간을 제한한다.
- 유사 이미지: 로컬 이미지 특징을 비교해 최대 30개를 표시한다. 유사도만으로 자료를 병합하거나 삭제하지 않는다.
- 새 설정·검색·모음·분류 기록·추출 내용을 백업에 포함했다. DB v1은 안전 사본을 만든 뒤 v2로 변환하고, 이전 ZIP 백업도 복원할 수 있게 했다. README·사용설명서·기획서의 구현 상태를 갱신했다.

### 설계 결정

- CLIP ONNX 이미지 모델은 고정 버전과 SHA-256을 검증해 설치한다. 이미지 분석과 OCR은 PC에서 수행한다. 모델은 자료함 ZIP과 분리해 재설치할 수 있다.
- 분류 점수는 비슷한 수동 사례 상위 3개의 평균 유사도다. 정확도 확률로 표시하지 않는다. 합성 자료에서 단색 이미지가 0.895로 추천된 사례를 확인해 기본 임계값을 0.9로 설정했다. 실제 사용자 자료에 대한 정확도 보장은 하지 않는다.
- 자동 태그가 있는 자료의 제목·메모만 수정해도 태그가 학습 사례로 확정되는 문제를 막았다. 확인함 승인이나 명시적인 수동 태그 지정으로만 확정한다. 거절한 추천은 재분석해도 자동으로 다시 붙이지 않는다.
- 요약은 생성형 AI 대신 원문 문장을 추출한다. 출처를 확인할 수 있지만 문맥 이해와 한국어 키워드 추출 품질은 제한적이다.
- 다운로드·자동 요약·OCR·키워드별 자동 분류는 기본적으로 꺼 둔다. 분석 실패 시 업로드한 원본은 유지한다. 분석 중 복원과 종료는 작업 완료 후 수행하도록 막는다.
- 링크 접속은 확인한 공개 IP에 연결을 고정하고 TLS 호스트 검증을 유지한다. 로그인·쿠키·저장 제한을 우회하지 않는다.

### 검증

## 2026-10-12 — HEAD 요청의 일회용 백업 다운로드 권한 보존

- 목표: 파일 헤더만 확인하는 HEAD 요청 때문에 실제 ZIP 다운로드 권한이 소모되는 문제를 수정한다.
